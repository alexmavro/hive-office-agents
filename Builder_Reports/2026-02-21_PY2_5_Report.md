# Builder Report: Pydantic Structural Hardening (PY.2 - PY.5)

**Date:** 2026-02-21  
**Author:** Antigravity  
**Branch:** Secure  

## Executive Summary
After implementing PY.1 (`SecretStr` on credentials), we expanded the scope to address all remaining Pydantic structural vulnerabilities identified in the governance documentation (`pydantic-governance.md`). These changes eliminate injection vectors via environment variables and structurally prevent silent configuration errors from causing runtime logic failures.

## 1. Environment Variable Masking (PY.1 / PY.2)
**The Problem:** While we masked standard credentials like `api_key` in the previous session, `MCPServerConfig.env` accepted arbitrary dictionaries of environment variables which often contain highly sensitive API keys (e.g., passing a brave API key or database credential into an MCP server). Because the dictionary values were plaintext strings, they were vulnerable to traceback and logging leaks.
**The Fix:** 
- Modified `MCPServerConfig.env` from `dict[str, str]` to `dict[str, SecretStr]` inside `hive/config/schema.py`.
- Updated `hive/agent/tools/mcp.py` to intercept the initialization of `StdioServerParameters` and actively unwrap the dictionary values using `.get_secret_value()`.

## 2. SSRF Validator on `web_fetch` (PY.2)
**The Problem:** The `web_fetch` tool makes HTTP requests from the host VPS. Previously, an attacker could instruct Queen to fetch an external public URL that automatically redirects to a local internal IP address (e.g., `169.254.169.254` AWS metadata endpoints, or `127.0.0.1`), bypassing standard URL scheme checks and allowing Server-Side Request Forgery.
**The Fix:**
- Imported `ipaddress` to build a hardcoded `_BLOCKED_NETWORKS` list covering all standard private and loopback networks.
- Intercepted the URL resolver pre-flight via `_is_private_host()`.
- Validated the `final_host` *after* the request completes via `r.url` blocking any malicious redirects. 

## 3. Strict Boundary Enforcement (PY.3 - PY.5)
**The Problem:** Basic Pydantic configuration models were incredibly loose. Integers had no bounds (e.g., `report_hour` could be set to 100), Enums were loose strings (typos silently failed logic), and unknown dictionary keys were silently dropped (e.g., `maxTokenns: 99` caused the system to boot with default token limits instead of failing loudly).
**The Fix:**
- **PY.3 (Numerics):** Applied `Field(ge=..., le=...)` caps to `AgentDefaults`, `AuditConfig`, `EmailConfig`, and `GatewayConfig`.
- **PY.4 (Literals):** Swapped vague string inputs for explicit `Literal[...]` types across all Channel settings (e.g., enforcing `"socket"` instead of `"socekt"`).
- **PY.5 (Strict Extras):** Appended `model_config = ConfigDict(extra='forbid')` to all leaf endpoints. Typos in user configuration files will now immediately crash the daemon on startup with a precise `ValidationError` rather than acting unpredictably.

## Conclusion & Next Steps
All 473 tests passed flawlessly, proving that narrowing the boundaries of structural data parsing had no impact on legacy operational logic.

This concludes the `PY` branch of the Security Roadmap. The baseline for data integrity is solid, bringing us significantly closer to being ready for S4 worker deployments.
